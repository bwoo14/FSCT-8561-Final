# FSCT 8561 Final Exam: Secure Evidence Delivery

A Python client/server system that checks a target service with nmap, recovers a hidden manifesto from `evidence.png`, logs in with a password and a TOTP code, agrees on an encryption key with the server and delivers the manifesto encrypted. The server only stores evidence that passes every check, and the client only reports success when the server's SHA-256 matches its own file.

**Test environment only.** Everything runs on localhost (127.0.0.1:12345). Only scan systems you own or are authorized to test.

## Contents

```
client/
  main.py            discovery check, TLS connection, login, menu
  tcp_scan.py        network discovery (nmap -sV), writes scan_results.csv
  handle_auth.py     client side of AUTH and OTP
  handle_command.py  menu actions: recover evidence, send evidence, message
  photo_scan.py      Stepic-style LSB recovery of the manifesto (Pillow)
  framing.py         length-prefixed framing
  crypto_utils.py    AES-256-GCM, X25519, HKDF (same as server)
  test_transmission.py  T08 helper: sends EVIDENCE with no login
  certs/server.crt   pinned server certificate (public part only)
  evidence/evidence.png        the original image (never modified)
server/
  main.py            TLS listener and per-connection handling
  handle_auth.py     Argon2id password check, TOTP, replay protection, lockout
  handle_command.py  token check, key exchange, evidence verification and storage
  handle_logging.py  timestamped log (console + server_log.csv)
  framing.py, crypto_utils.py
  enroll.py          creates a user (users.json)
  gen_cert.py        creates the self-signed certificate
requirements.txt
```

## 1. Requirements

- Python 3.12 or newer (the code uses nested quotes inside f-strings).
- The **nmap program** installed and on your PATH (the Python package `python-nmap` is only a wrapper).
  - Windows: install from https://nmap.org/download and tick the option to add it to PATH. Check with `nmap --version`.
  - Debian/Ubuntu: `sudo apt install nmap`
  - macOS: `brew install nmap`
- An authenticator that can generate TOTP codes from a base32 secret (Google Authenticator, Aegis, or any TOTP tool). Use a throwaway secret that is only for this exam.

## 3. Generate the secrets (nothing secret is included in this submission)

The submission contains no `users.json` and no `server.key`. Create them yourself:

**a) Server certificate.** Run from inside `server/` (it writes to `./certs`):
```
cd server
py gen_cert.py          # Linux/macOS: python3 gen_cert.py
```
This creates `server/certs/server.crt` (public) and `server/certs/server.key` (private, stays on the server).
The certificate is self-signed ECDSA P-256, valid one year, with subject alternative names `localhost`, `127.0.0.1` and `::1`.

**b) Pin the certificate on the client.** Copy ONLY the public certificate:
```
copy server\certs\server.crt client\certs\server.crt        # Windows
cp server/certs/server.crt client/certs/server.crt          # Linux/macOS
```
The client trusts only this certificate. Never copy `server.key` to the client. If you regenerate the certificate, copy it again, otherwise the client will refuse to connect.

**c) Create a test user.** Run from inside `server/`:
```
py enroll.py
```
Enter a username, then a password twice. The script prints a base32 TOTP secret and saves an Argon2id password hash and the secret to `server/users.json`. Add the secret to your authenticator. Enroll a separate throwaway user for each automated or screenshot run if you need independent replay state, because a TOTP code can only be used once per user.

## 4. Run

Open two terminals with the virtual environment active.

**Terminal 1, server:**
```
cd server
py main.py
```
Expected: `Server listening on 127.0.0.1:12345 (TLS on)`.

**Terminal 2, client:**
```
cd client
py main.py
```
1. Discovery: enter the target host (`localhost`) and a start and end port (for example `12345` to `12345`, or `12340` to `12350`). Findings are printed and saved to `scan_results.csv`.
2. If port 12345 is **not** open, the client prints that the required service is unavailable and exits (this is test T02). Start the server first.
3. Enter the username, password, then the current TOTP code.
4. Menu: `[1] Recover Evidence`, `[2] Send Evidence`, `[3] Message Server`, `[4] Exit`.

Typical full run: `1` (recovers `evidence/architect_manifesto.txt` and shows the hashes), then `2` (the client prints `DELIVERED and verified` only when the server's hash matches).

## 6. Configuration

| Setting | Where | Default |
|---|---|---|
| Host and port | `HOST`, `PORT` in `client/main.py` and `server/main.py` | 127.0.0.1, 12345 |
| Pinned certificate | `cafile` in `client/main.py` | `certs/server.crt` |
| Lockout | `LOGIN_ATTEMPT_MAX`, `LOCKOUT_SECONDS` in `server/handle_auth.py` | 3 failures, 60 s |
| Idle timeout | `CLIENT_TIMEOUT` in `server/main.py` | 60 s |
| Size limits | `MAX_CONTROL`, `MAX_EVIDENCE` in `framing.py` | 4096 bytes, 1 MiB |
| `FSCT_USE_TLS=0` | environment variable on **both** sides | TLS on |

`FSCT_USE_TLS=0` turns TLS off and exists only so the traffic-capture test (T09) can be compared with and without TLS. In that mode the password, OTP and session token are sent in cleartext. Never use it outside a controlled lab.

## 8. Troubleshooting

- **"Required service unavailable"**: the server is not running, or nmap is not installed or not on PATH.
- **"Server certificate could not be verified"**: `client/certs/server.crt` is missing or is not the certificate the server is using. Copy it again from `server/certs/`.
- **Login always fails**: the codes must come from the secret printed by `enroll.py`, your computer clock must be accurate (only the current 30 second code is accepted), and a code cannot be used twice.
- **"Account locked"**: wait 60 seconds. The lock is in memory and also clears if the server restarts.

## 9. Security notes

- Nothing secret is submitted: no `users.json`, no `server.key`, no real passwords or TOTP secrets. `.gitignore` excludes them.
- Passwords are stored as salted Argon2id hashes only. TOTP secrets are stored in plaintext in `users.json` because the server needs them to verify codes (listed in the report's limitations).
- The key for AES-256-GCM is never stored or sent. It is derived per session from an ephemeral X25519 exchange inside the TLS session.
- See the report for the full design, test matrix and limitations.
